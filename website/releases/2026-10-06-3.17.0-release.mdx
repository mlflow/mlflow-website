MLflow 3.17.0 brings typed decisions into evaluation and tracing, finer control over access to shared resources, and faster analytics for large trace datasets. This release also improves evaluation result attribution and saved Assistant conversations on shared servers.

## 1. **Jev Decisions Across Evaluation, Tracing, and Gateway**

### Evaluate Answers with Jev Judges

<img
  src="/img/releases/3.17.0/jev-eval-final.png"
  alt="A custom Jev judge using typesafe:/jev-latest, with its answer-correctness assessment displayed in MLflow."
  width="100%"
  style={{ display: "block", marginBottom: 24 }}
/>

TypeSafe's Jev System One models offer a fast, low-cost option for yes/no and finite-category evaluation. Use `model="typesafe:/jev-latest"` with built-in scorers or custom judges in `mlflow.genai.evaluate()`. Results are recorded as MLflow assessments, with probabilities and category distributions in the metadata so you can identify close calls. Pin a versioned model ID when comparing results across evaluation runs.

[Learn more about Jev judges](https://mlflow.org/docs/latest/genai/eval-monitor/scorers/llm-judge/custom-judges/typesafe/)

### Inspect System One Decisions in Traces

<img
  src="/img/releases/3.17.0/jev-trace-final.png"
  alt="The MLflow trace viewer showing System One input state, questions, structured answers, and a category probability distribution."
  width="100%"
  style={{ display: "block", marginBottom: 24 }}
/>

Follow each decision from its inputs to its result. Enable `mlflow.typesafe.autolog()` to trace synchronous and asynchronous TypeSafe calls, capturing state, questions, structured answers, latency, errors, and token usage when reported by the SDK. The trace viewer presents selected answers alongside their probability distributions and confidence, helping you investigate unexpected decisions. JavaScript and TypeScript applications can use `tracedTypeSafe()` for the same visibility.

[Learn more about TypeSafe tracing](https://mlflow.org/docs/latest/genai/tracing/integrations/listing/typesafe/)

### Govern Jev Access Through AI Gateway

<img
  src="/img/releases/3.17.0/jev-gateway-final.png"
  alt="The AI Gateway model selector listing TypeSafe Jev evaluation models with jev-latest selected."
  width="100%"
  style={{ display: "block", marginBottom: 24 }}
/>

Manage Jev access centrally instead of distributing provider API keys to every application. Create a TypeSafe System One endpoint in AI Gateway to keep credentials on the server and manage access, usage tracking, and budgets in one place. Configure fallbacks to compatible System One models, including OpenRouter Jev decision models, to handle provider errors or rate limits. Judges can use a `gateway:/` endpoint from the SDK or the evaluation UI, while endpoint configuration changes stay in the Gateway.

[Learn more about TypeSafe in AI Gateway](https://mlflow.org/docs/latest/genai/governance/ai-gateway/endpoints/model-providers/#typesafe)

## 2. **Fine-Grained Permissions for Shared Resources**

<img
  src="/img/releases/3.17.0/resource-permissions-final.png"
  alt="Python permission example allowing an experiment-reader role to read experiments while denying access to traces."
  width="100%"
  style={{ display: "block", marginBottom: 24 }}
/>

Give collaborators access to an experiment without automatically exposing every kind of resource inside it. Role-based access control now covers runs, traces, assessments, logged models, review queues, and model, prompt, scorer, and MCP-server versions. Administrators can configure these permissions in the Admin UI or through the Python client.

The new `DENY` permission makes exceptions to broader grants explicit. For example, a reviewer can read experiments while being denied access to traces. Permissions for the new resource types use wildcard scope, bounded by access to their parent containers; individual run or trace IDs are not supported as grant patterns. Existing container permissions continue to apply when no grant is set for a contained resource type.

[Learn more about resource permissions](https://mlflow.org/docs/latest/self-hosting/security/role-based-access-control/#sub-resource-tiers)

## 3. **Faster Analytics for Large Trace Datasets**

<img
  src="/img/releases/3.17.0/trace-analytics-final.png"
  alt="Opt-in SQL daily rollups use historical summaries alongside raw queries for recent, partial, or uncovered data to serve trace analytics."
  width="100%"
  style={{ display: "block", marginBottom: 24 }}
/>

Spend less time waiting for trace dashboards as your datasets grow. SQL-backed analytics now reduce query overhead for trace counts, latency, token usage, costs, and assessments. Optional daily rollups reuse precomputed summaries for eligible historical data, while recent data, partial days, and unsupported queries continue through the raw query path. Trace search and retrieval also avoid unnecessary database and serialization work.

Administrators can enable rollups with `MLFLOW_SQL_TRACE_ROLLUPS_ENABLED=true` after completing the documented database upgrade and maintenance setup. This schema transition requires a coordinated upgrade with writers stopped; mixed-version rolling upgrades are not supported. The database guide includes an optional resumable preparation command for large installations.

[Learn more about trace analytics rollups](https://mlflow.org/docs/latest/self-hosting/architecture/backend-store/#trace-analytics-daily-rollups)

## 4. **Clearer Evaluation Results**

<img
  src="/img/releases/3.17.0/evaluation-dataset-id-final.png"
  alt="A dataset details page displaying its dataset ID with a copy button."
  width="100%"
  style={{ display: "block", marginBottom: 24 }}
/>

Evaluation results are easier to connect to the model and dataset that produced them. Evaluating a logged model against a managed dataset now records the dataset name and digest on aggregate metrics. Assessment summaries on a logged model's Traces page also match that model's traces.

The dataset details page displays a copyable dataset ID, so you can move from the UI to the SDK without extracting it from the browser URL.

_Thanks to community contributor [@janald99](https://github.com/janald99) for the dataset ID improvement!_

[Learn more about evaluation datasets](https://mlflow.org/docs/latest/genai/datasets/)

## 5. **Assistant Improvements for Shared Servers**

Saved Assistant conversations are now scoped to the signed-in user. Switching accounts resets the active session and unfinished prompt, so the next person using the same browser starts with their own conversation. Experimental sandbox deployments also align the fallback container's Python and released MLflow versions with the server.

[Learn more about MLflow Assistant](https://mlflow.org/docs/latest/genai/getting-started/try-assistant/)
