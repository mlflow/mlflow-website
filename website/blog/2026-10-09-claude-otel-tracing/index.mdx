Agents built on Claude can run for dozens of turns on a single task: calling the model, running tools, and calling the model again after each step. When a run goes wrong, the final answer rarely tells you why. Which tool call returned something unexpected? How many tokens did that long run actually burn, and what did it cost?

Claude can now answer those questions natively. Claude Managed Agents, the Messages API, the Claude SDKs, and Claude Code all emit OpenTelemetry (OTel) traces, covering each model request and tool call, and any backend that speaks the OpenTelemetry Protocol (OTLP) can receive them. You need no adapter code and no collector.

This tutorial shows how to set up that export for each Claude product. We send the traces to MLflow because it is open source and doesn't need a sign-up for any service.

## How it fits together

Claude sends traces with OTLP over HTTP. In this tutorial they go to a local MLflow server, which receives them at `/v1/traces`:

```
+----------------+                         +---------------+            +------------+
|  Claude Code   |                         | MLflow server |            |   MLflow   |
|   Agent SDK    |        OTLP/HTTP        |               |            | tracing UI |
|  Claude SDKs   | ----------------------> |   translates  | ---------> |            |
|  Messages API  |     POST /v1/traces     |  Claude spans |            |            |
| Managed Agents |                         |               |            |            |
+----------------+                         +---------------+            +------------+
```

## Prerequisites

- **MLflow 3.17.1 or newer** on the server side (`pip install "mlflow>=3.17.1"`)
- The Claude product you want to trace.

## Step 1: Start an MLflow server and create an experiment

Start an MLflow server locally:

```bash
mlflow server --host 127.0.0.1 --port 5000
```

Create an experiment for your traces (`mlflow experiments create -n claude-traces`) and note its numeric ID. You will pass that ID to Claude in the next step, to specify which experiment the traces belong to.

## Step 2: Send Claude traces via OTLP

Every product sends traces to the same place: the MLflow endpoint `http://<your-server>/v1/traces`, with the header `x-mlflow-experiment-id: <your experiment ID>`.

### Claude Platform UI: Messages API and Managed Agents

You can also configure tracing for Messages API requests and Managed Agents sessions directly in Claude Platform. For this flow, Anthropic sends traces from its infrastructure, so use an HTTPS MLflow server that Anthropic can reach and enable [MLflow authentication](https://mlflow.org/docs/latest/self-hosting/security/basic-http-auth/) on that server.

1. Open [Claude Platform](https://platform.claude.com/) and select **OpenTelemetry** in the sidebar.
2. Click **+ Add destination**.
3. Select **Custom** as the **Provider** to connect an OTLP-native backend such as MLflow.
4. Fill in the destination fields:

   | Field                 | Value                                                                                                                                                                                   |
   | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | **Name** (optional)   | A name such as `MLflow OpenTelemetry Backend`                                                                                                                                           |
   | **OTLP endpoint URL** | `https://YOUR_MLFLOW_SERVER/v1/traces`                                                                                                                                                  |
   | **Request headers**   | Add `x-mlflow-experiment-id` as the header name and your experiment's numeric ID as its value. Add any authentication headers required by your MLflow deployment as additional headers. |

5. Choose a **Content mode**. Select **Full content** to record message and tool content for deeper analysis and evaluation. Choose **Metadata only** if you only need statistics such as latency and token counts, without message or tool content.
6. Select the **Workspaces** whose activity you want to export, then click **Add destination**.

### Claude SDKs and the Messages API

The Claude SDKs create an OpenTelemetry span for each Messages API call. Like other OpenTelemetry-native libraries, they send spans to whatever exporter your application sets up, so the only setup is to point an OpenTelemetry exporter at MLflow before you create the client.

**Python:**

```bash
pip install anthropic opentelemetry-sdk opentelemetry-exporter-otlp-proto-http
```

```python
import anthropic
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor

provider = TracerProvider()
provider.add_span_processor(
    BatchSpanProcessor(
        OTLPSpanExporter(
            endpoint="http://127.0.0.1:5000/v1/traces",
            headers={"x-mlflow-experiment-id": "YOUR_EXPERIMENT_ID"},
        )
    )
)
trace.set_tracer_provider(provider)

client = anthropic.Anthropic()
message = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Hello, Claude"}],
)
```

**TypeScript:**

```bash
npm install @anthropic-ai/sdk @opentelemetry/sdk-trace-node@^2.11.0 @opentelemetry/sdk-trace-base@^2.11.0 @opentelemetry/exporter-trace-otlp-proto@^0.222.0
```

```typescript
import Anthropic from "@anthropic-ai/sdk";
import { NodeTracerProvider } from "@opentelemetry/sdk-trace-node";
import { BatchSpanProcessor } from "@opentelemetry/sdk-trace-base";
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-proto";

const provider = new NodeTracerProvider({
  spanProcessors: [
    new BatchSpanProcessor(
      new OTLPTraceExporter({
        url: "http://127.0.0.1:5000/v1/traces",
        headers: { "x-mlflow-experiment-id": "YOUR_EXPERIMENT_ID" },
      }),
    ),
  ],
});
provider.register();

const client = new Anthropic();
const message = await client.messages.create({
  model: "claude-sonnet-5-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Hello, Claude" }],
});
```

### Claude Managed Agents

Claude Managed Agents run on Anthropic's infrastructure. Set the OTLP trace endpoint to your MLflow server's `/v1/traces` URL and add the header `x-mlflow-experiment-id: <your experiment ID>`. If the traces are sent from Anthropic's side, the server needs a URL Anthropic can reach; turn on [MLflow authentication](https://mlflow.org/docs/latest/self-hosting/security/basic-http-auth/) before you expose it.

### Claude Code

Claude Code's OTel export is configured entirely through environment variables. The first six are required; the last three are optional. Add them to your shell (or to a `.env` file you source before launching `claude`):

```bash
# Required: turn telemetry on and enable trace spans.
export CLAUDE_CODE_ENABLE_TELEMETRY=1
export CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1

# Required: export traces with OTLP over HTTP.
export OTEL_TRACES_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf

# Required: the MLflow endpoint (note the full /v1/traces path), and the
# x-mlflow-experiment-id header that tells MLflow where to file the traces.
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://127.0.0.1:5000/v1/traces
export OTEL_EXPORTER_OTLP_TRACES_HEADERS=x-mlflow-experiment-id=YOUR_EXPERIMENT_ID

# Optional: include prompt and tool content, which is redacted by default.
export OTEL_LOG_USER_PROMPTS=1
export OTEL_LOG_TOOL_DETAILS=1
export OTEL_LOG_TOOL_CONTENT=1
```

Launch `claude` and work normally; when the session ends, the trace lands in your MLflow experiment.

### Claude Agent SDK

The Claude Agent SDK (Python and TypeScript) runs the Claude Code CLI as a child process and passes configuration through to it, so it uses the Claude Code setup above: set those environment variables in the process that starts the SDK, and every SDK session produces the same traces.

**Python:** the SDK merges its `env` option onto the inherited environment, so exporting the variables before running your script is enough:

```python
import asyncio

from claude_agent_sdk import ClaudeAgentOptions, query


async def main():
    # The OTel environment variables above are inherited by the CLI child
    # process, so no SDK-specific configuration is needed.
    async for message in query(
        prompt="Summarize the failing tests in this repo",
        options=ClaudeAgentOptions(),
    ):
        print(message)


asyncio.run(main())
```

**TypeScript:** one real gotcha: `options.env` **replaces** the child process environment rather than extending it. If you pass an `env` object, spread `process.env` first, or your OTel variables will never reach the CLI:

```typescript
import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Summarize the failing tests in this repo",
  options: {
    env: {
      // options.env replaces the environment, so inherit it explicitly:
      ...process.env,
      CLAUDE_CODE_ENABLE_TELEMETRY: "1",
      CLAUDE_CODE_ENHANCED_TELEMETRY_BETA: "1",
      OTEL_TRACES_EXPORTER: "otlp",
      OTEL_EXPORTER_OTLP_TRACES_PROTOCOL: "http/protobuf",
      OTEL_EXPORTER_OTLP_TRACES_ENDPOINT: "http://127.0.0.1:5000/v1/traces",
      OTEL_EXPORTER_OTLP_TRACES_HEADERS:
        "x-mlflow-experiment-id=YOUR_EXPERIMENT_ID",
      OTEL_LOG_USER_PROMPTS: "1",
      OTEL_LOG_TOOL_DETAILS: "1",
      OTEL_LOG_TOOL_CONTENT: "1",
    },
  },
})) {
  console.log(message);
}
```

Two SDK-specific caveats:

- **Do not use the `console` OTel exporter through the SDK.** The SDK and the CLI communicate over stdout, and console export corrupts that channel. Use the `otlp` exporter as shown.
- **Exporter failures are silent by default.** If traces are not arriving, set `CLAUDE_CODE_OTEL_DIAG_STDERR=1` to get OTel diagnostics on stderr instead of guessing.

## Going deeper with Claude Code: response text and context snapshots

By default, Claude Code's model-request spans carry token counts but not the model's response text, and the exact context sent to the model is not included in the export. Claude Code has an additional detailed-tracing mode for exactly this. Setting

```bash
export ENABLE_BETA_TRACING_DETAILED=1
export BETA_TRACING_ENDPOINT=http://127.0.0.1:5000/v1/traces
```

adds `response.model_output` (the model's reply), `new_context` (the context snapshot), `tool_input` (tool inputs in full), and a few system-prompt attributes. The model's reply then appears as the model call's output:

## Troubleshooting

- **No Claude Code traces appear.** Confirm both `CLAUDE_CODE_ENABLE_TELEMETRY` and `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA` are set. The first is the master switch, the second enables span tracing. Set `CLAUDE_CODE_OTEL_DIAG_STDERR=1` to surface exporter errors.
- **Everything is `<REDACTED>` in Claude Code traces.** That is the privacy default; set the `OTEL_LOG_*` toggles from Step 2.

## Wrapping up

Your Claude agents now tell you what they did. Because the setup is plain OTLP, it works the same way with other OTLP backends; only the endpoint and headers change.
